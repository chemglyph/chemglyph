# M3 — Validation + naming + MCP

## Status

Completed 2026-08-13. Local test suite: 54 passed, 1 skipped (the optional
OPSIN/Java naming path). MCP server verified end to end over stdio by the
integration tests (initialize → list_tools → call_tool for all four tools).

## Completed

- `validate.py`: the four quick-fix rules and the full `ValidationReport`
  (implemented in M1 because §5 parse errors depend on it; M3 adds the
  dedicated test file).
- `naming.py`: English names via the optional `py2opsin`/OPSIN (Java
  checked up front, friendly `ChemGlyphDependencyError` otherwise); Chinese
  names raise `NotImplementedError` ("planned for v0.2"); no online lookup.
- `mcp_server.py`: official MCP SDK over stdio, exposing `render_molecule`,
  `render_reaction`, `validate_structure`, `parse_name` as tools. SVGs come
  back as `ImageContent` (`image/svg+xml`) with a `TextContent` metadata
  block; PNG returns `image/png`; every tool docstring starts with a
  "use this when" sentence and includes an input example.
- `tests/test_mcp_server.py`: real stdio round-trips with the official MCP
  client (tool discovery + all four calls).
- `docs/claude_desktop_config.json`: registration snippet for Claude Desktop.

## Deviations from spec (and why)

1. The spec says "FastMCP style" for the MCP SDK; the current official SDK
   (mcp 2.x, installed here) replaced `FastMCP` with `MCPServer` and the
   `@server.tool()` decorator. ChemGlyph uses the current official high-level
   API (the closest equivalent of FastMCP).
2. Tool result error fields use the SDK's current `is_error` shape; tool
   names are pinned with `name=` so they match §9 exactly.
3. The nitro example in §7 rule 2 (`c1ccccc1N(=O)=O`) now parses natively in
   current RDKit (it auto-corrects the nitro group); the kekulize rule is
   tested with `c1cccc1 → C1CCCC1` instead.
4. `py2opsin` is not installed in the dev environment, so the live English
   name-resolution test skips until the maintainer installs the `opsin` extra
   and a Java runtime.
